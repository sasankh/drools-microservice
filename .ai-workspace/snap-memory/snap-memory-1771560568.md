## 🔍 Problems Identified

### Problem 1: Endpoint Routing Conflict (CRITICAL)

**Symptom**: All endpoints returning 404 NOT_FOUND
```bash
curl http://localhost:8081/actuator/health → 404
curl http://localhost:8080/admin/rules → 404
curl http://localhost:8080/admin/thread-pools → 404
curl http://localhost:8080/admin/memory/info → 404
```

**Investigation Process**:
1. Tested all endpoints - confirmed all 12 returning 404
2. Checked application logs - saw "Exposing 3 endpoint(s) beneath base path '/admin'"
3. Reviewed application.yml - found `management.endpoints.web.base-path: /admin`
4. Reviewed AdminController - found `@RequestMapping("/admin")`
5. **Root Cause**: Path collision - both Actuator and custom controllers using `/admin/*`

**Impact**: Complete API failure - no endpoints accessible

### Problem 2: Drools Rule Compilation Failure (CRITICAL)

**Symptom**: All rules failing to compile
```
ERROR: Unable to resolve ObjectType 'Map'
ERROR: Rule Compilation error $data cannot be resolved
```

**Investigation Process**:
1. Attempted to load sample rules from S3 - all failed (0 loaded, 11 failed)
2. Checked application logs - compilation errors for all rules
3. Downloaded and inspected sample rules - missing `import java.util.Map`
4. Added import to test rule - compilation succeeded
5. **Root Cause**: Drools requires explicit import even for standard Java classes

**Impact**: No rules could execute, core functionality broken

## 🎓 Key Learnings

### 1. Spring Boot Endpoint Port Architecture (CRITICAL)

**Discovery**: Custom `@RestController` endpoints are NOT served on the management port

**Rule**:
- **Port 8081 (Management)**: Spring Boot Actuator ONLY (`/actuator/*`)
- **Port 8080 (Application)**: Main API + Custom Admin endpoints

**Common Mistake**:
```yaml
# ❌ WRONG - Causes path conflict
management:
  server:
    port: 8081
  endpoints:
    web:
      base-path: /admin  # Conflicts with @RequestMapping("/admin")

# ✅ CORRECT - Separate paths
management:
  server:
    port: 8081
  endpoints:
    web:
      base-path: /actuator  # Different from /admin
```

**Why This Matters**: Even though AdminController exists, it serves on port 8080, not 8081. Setting Actuator base path to `/admin` causes ALL `/admin/*` requests to route to Actuator first, which then returns 404 for non-Actuator paths.

### 2. Drools Import Requirements (CRITICAL)

**Discovery**: Drools requires explicit imports for ALL types, including standard Java classes

**Rule**: Every `.drl` file that uses `Map` MUST include:
```drools
import java.util.Map
```

**Why This Happens**:
- Drools uses its own class loader and type resolution
- Does not automatically import java.util.*
- Even though Map is a standard class, Drools can't resolve it without explicit import

**Batch Compilation Impact**:
- Rules compile together as a batch
- One broken rule fails the ENTIRE compilation
- Result: 0 rules loaded instead of 10 rules (even if only 1 has error)

**Error Pattern to Watch For**:
```
ERROR: Unable to resolve ObjectType 'Map'
ERROR: Rule Compilation error $data cannot be resolved
```
**Solution**: Always add `import java.util.Map` at the top of .drl files

### 3. API Request Format

**Discovery**: JSON field names use snake_case, not camelCase

**Wrong**:
```json
{
  "ruleId": "pricing.discount.simple",  // ❌ Will be null
  "data": {"amount": 100}
}
```

**Correct**:
```json
{
  "rule_id": "pricing.discount.simple",  // ✅ Matches @JsonProperty
  "data": {"amount": 100}
}
```

**Why**: DTO uses `@JsonProperty("rule_id")` annotation
```java
public class RuleExecutionRequest {
  @JsonProperty("rule_id")  // ← Uses snake_case
  private String ruleId;     // ← Java field is camelCase
}
```

### 4. Spring Boot 3.x Path Matching Behavior

**Discovery**: Spring Boot 3.x is very strict about path matching and handler selection

**Behavior**:
1. `CompositeHandlerAdapter` tries multiple handlers in order
2. If Actuator is configured with `/admin` base path, it matches `/admin/*` FIRST
3. Custom controllers with `@RequestMapping("/admin")` never get a chance to handle
4. Result: 404 errors for all custom endpoints

**Solution**: Use completely different base paths for Actuator vs custom controllers

### 5. Debugging Endpoint Issues

**Effective Strategy**:
1. Check application logs for "Exposing X endpoint(s) beneath base path '/...'"
2. Test endpoints on BOTH ports (8080 and 8081)
3. Look for path conflicts in application.yml and @RequestMapping
4. Understand that custom controllers serve on main port, not management port

**Tools Used**:
```bash
# Check what Actuator base path is configured
grep -A 3 "management:" application.yml

# Test both ports
curl http://localhost:8080/admin/health  # Custom controller
curl http://localhost:8081/actuator/health  # Actuator

# Check logs for endpoint registration
docker-compose logs app | grep "Exposing.*endpoint"
```
