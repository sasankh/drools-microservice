## PROBLEM SOLVING

### Errors Encountered

**Error 1: DRL ClassCastException - Integer cannot be cast to Double**
- Error: `java.lang.ClassCastException: class java.lang.Integer cannot be cast to class java.lang.Double`
- When: Executing any rule that reads numeric "amount" from JSON data in Docker
- Root cause: Jackson deserializes JSON integers (150, 200) as `java.lang.Integer`, but DRL rules cast with `(Double) $data.get("amount")`. Only affects rules with numeric values sent without decimal points.
- Solution: Changed all DRL rules to use `((Number) $data.get("field")).doubleValue()` which handles both Integer and Double
- Affected files: All 10 sample DRL rules + 4 hardcoded rules in init-localstack.sh
- Prevention: Added documentation in ai-initial-context noting this as a required DRL pattern

**Error 2: init-localstack.sh uploads old rules**
- When: Running `bash init-localstack.sh` after fixing sample-rules/ files
- Root cause: The script has two code paths: (1) upload from mounted /tmp/sample-rules/ dir, (2) use hardcoded DRL strings. The hardcoded path still had old `(Double)` casts.
- Solution: Updated both paths - fixed hardcoded rules in init-localstack.sh AND manually uploaded fixed files from sample-rules/ via awslocal CLI

**Error 3: Admin endpoints on wrong port in Docker**
- When: Testing `curl http://localhost:8081/admin/health` returned 404
- Root cause: In Docker, admin endpoints are served on port 8080 (same as main API), not 8081. Port 8081 appears to serve a different Spring dispatcher without admin routes.
- Solution: Used port 8080 for all Docker endpoint tests. Documented in ai-initial-context.

**Error 4: API request used wrong field name**
- When: First Docker rule execution attempt returned `INVALID_INPUT - Rule ID cannot be null`
- Root cause: Request body used `{"ruleId": "..."}` but the DTO uses `@JsonProperty("rule_id")` so the field must be `rule_id` (snake_case)
- Solution: Corrected all test requests to use `{"rule_id": "..."}`

## DECISION LOG

### Architecture Decisions
**Decision:** Use `((Number) ...).doubleValue()` pattern for all DRL numeric access
**Alternatives:**
1. Cast to `(Double)` - fails with JSON integers
2. Send all numbers as decimals in API requests - fragile, requires client awareness
3. Pre-process data in Java before DRL execution - overhead, complexity
4. Use `((Number) ...).doubleValue()` (chosen) - handles both Integer and Double from JSON

**Rationale:** JSON/Jackson deserializes integers (no decimal) as `java.lang.Integer` and decimals as `java.lang.Double`. Since API consumers naturally send `{"amount": 100}` not `{"amount": 100.0}`, the DRL rules must handle both types. `Number` is the common superclass.

**Trade-offs:** Slightly more verbose DRL syntax, but zero ambiguity.

## KNOWLEDGE CAPTURE

### Things Learned
- JSON numeric types: Jackson parses `100` as Integer, `100.0` as Double. DRL rules accessing Map values must account for this.
- Docker port mapping: In docker-compose, both main and admin endpoints may serve on the same port depending on Spring configuration
- `@JsonProperty("rule_id")` means the JSON field is `rule_id` (snake_case), not the Java field name `ruleId`
- init-localstack.sh has a dual path: mounted sample-rules dir OR hardcoded inline DRL strings

### Gotchas & Pitfalls
1. **DRL Number casting**: NEVER use `(Double) map.get("key")` for JSON-sourced data. ALWAYS use `((Number) map.get("key")).doubleValue()`. This applies to all DRL rules that read numeric values from the execution data map.
2. **init-localstack.sh dual path**: The script has hardcoded DRL rules as a fallback if `/tmp/sample-rules/` isn't mounted. Both paths must be kept in sync when fixing DRL rules.
3. **Docker admin port**: Admin endpoints are on port 8080 in Docker (not 8081). The health check in docker-compose may also need to target the correct port.
4. **API field naming**: The JSON API uses snake_case (`rule_id`, `execution_time_ms`) not camelCase. This is controlled by `@JsonProperty` annotations on the DTOs.
