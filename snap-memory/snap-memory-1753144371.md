## ⚙️ **HOW** - Technical Implementation Details

### Architecture Pattern:
```
Client Request → REST API → DroolsEngineService → Cache Layer → Storage Layer
                    ↓           ↓                    ↓            ↓
               Controller → Rule Executor →    LRU/Redis →   S3/Local/Memory
```

### Key Design Decisions:
1. **Storage Abstraction**: Interface-based design with factory pattern
2. **Cache Strategy**: Read-through cache with manual invalidation
3. **Thread Safety**: ReentrantReadWriteLock for LRU, concurrent collections
4. **Error Handling**: Graceful degradation (Redis → LRU → S3)
5. **Rule ID Transformation**: `pricing.discount.vip` → `pricing/discount/vip.drl`

### Implementation Highlights:
- **S3 Retry Logic**: Exponential backoff with 3 attempts
- **Cache Statistics**: Hit/miss ratios, eviction counts, performance metrics
- **Admin Endpoints**: Comprehensive rule management with detailed responses
- **Docker Integration**: Multi-service setup with LocalStack and Redis

## ❌ **ERRORS ENCOUNTERED & SOLUTIONS**

### 1. S3Client Retry Policy Configuration
**Problem**: `retryPolicy()` method not found on S3ClientBuilder
```java
// FAILED
.retryPolicy(createRetryPolicy())

// SOLUTION
.overrideConfiguration(builder -> builder.retryPolicy(createRetryPolicy()))
```

### 2. Redis Serialization Issues  
**Problem**: Jackson2JsonRedisSerializer constructor changes in Spring Boot 3
```java
// FAILED
new Jackson2JsonRedisSerializer(Rule.class)

// SOLUTION  
new Jackson2JsonRedisSerializer<>(objectMapper, Rule.class)
```

### 3. LocalDateTime to Instant Conversion
**Problem**: JSON serialization issues with LocalDateTime in DTOs
```java
// FAILED
response.setTimestamp(metadata.getLoadedAt())

// SOLUTION
response.setTimestamp(metadata.getLoadedAt().atZone(ZoneOffset.UTC).toInstant())
```

### 4. Spring Bean Conflicts
**Problem**: Multiple RuleStorage implementations causing autowiring conflicts
```java
// SOLUTION
@Primary annotation on factory-created bean in StorageConfig
```

## 🏗️ **ARCHITECTURE DECISIONS**

### 1. Storage Abstraction Pattern
**Decision**: Interface-based storage with factory pattern
**Alternatives**: Direct S3 integration, single storage type
**Trade-off**: Added complexity for flexibility and testability

### 2. Multi-Tier Caching Strategy  
**Decision**: LRU → Redis → S3 hierarchy
**Alternatives**: Single cache layer, no caching
**Trade-off**: Memory usage for performance gains

### 3. Rule ID Path Transformation
**Decision**: Convert dots to slashes for S3 keys (`pricing.discount` → `pricing/discount.drl`)
**Alternatives**: Keep dots, use different delimiter
**Trade-off**: S3 path conventions vs. Java package naming

### 4. Admin API on Separate Port
**Decision**: Port 8080 (main API) + Port 8081 (admin)
**Alternatives**: Same port with /admin prefix
**Trade-off**: Network configuration for operational security

### 5. Thread-Safe Cache Implementation
**Decision**: ReentrantReadWriteLock with LinkedHashMap
**Alternatives**: ConcurrentHashMap, Caffeine cache
**Trade-off**: Custom implementation for specific LRU behavior
