## PROBLEM SOLVING

#### Error 1: Matcher.replaceAll with Method Reference
- **Error**: Attempted `LONG_TOKEN_PATTERN.matcher(sanitized).replaceAll(LogSanitizer::tokenReplacer)` — compile error
- **When**: Phase 8, implementing long token redaction
- **Root Cause**: Java 17's `Matcher.replaceAll(Function)` doesn't match a static method reference with the expected signature
- **Solution**: Created manual `redactLongTokens()` method using `while(matcher.find())` loop with `appendReplacement`/`appendTail`

#### Error 2: CircuitBreakerException Constructor Mismatch
- **Error**: `new CircuitBreakerException("S3 circuit breaker is open", e)` — no matching constructor
- **When**: Phase 9, wrapping getAllRules() with circuit breaker
- **Root Cause**: Project's `CircuitBreakerException` has constructor `(String circuitBreakerName, String state)`, not `(String message, Throwable cause)`
- **Solution**: Changed to `new CircuitBreakerException("s3", "OPEN")`

#### Error 3: Missing Methods After Reference
- **Error**: Compilation failures from referencing `redactLongTokens()`, `sanitizeNestedMap()`, `looksLikeClassName()` before writing them
- **When**: Phase 8, incremental LogSanitizer edits

## DECISION LOG

#### Decision: Non-Blocking Compilation (Phase 6)
- **Decision**: Move rule compilation outside the write lock; only hold write lock for atomic KieContainer swap
- **Rationale**: Compilation can take seconds for complex rule sets. Holding the write lock during compilation blocks ALL concurrent rule executions.
- **Trade-offs**: Brief window where old and new KieContainers coexist. Mitigated by atomic swap under write lock.
- **Impact**: Dramatically improves concurrency under rule refresh load

#### Decision: Word-Boundary Regex vs Substring Match (Phase 8)
- **Decision**: Use `\b` word boundaries for sensitive keywords (pin, auth, ssn, cvv)
- **Alternatives**: Full-word string matching, configurable pattern list
- **Rationale**: `\b` is simple, well-understood, and prevents false positives on "shipping" (contains "pin"), "author" (contains "auth") while still catching standalone sensitive terms
- **Trade-offs**: Won't catch "my_pin" or "pin_code" — acceptable since these would be caught by the SENSITIVE_KEYS set

#### Decision: Skip Redis Auth/TLS and Dependency Updates
- **Decision**: Skip fixes #28 (Redis auth/TLS) and #30 (dependency updates) per user request
- **Rationale**: Redis auth/TLS is an infrastructure change better suited for production deployment. Dependency updates require compatibility testing.

## KNOWLEDGE CAPTURE

#### Things Learned
- **Java's `Matcher.replaceAll(Function)`** requires a `Function<MatchResult, String>` — can't just pass a static method reference with different signature. Manual `appendReplacement` loop is more flexible.
- **Project's custom exceptions** have specific constructors — always check before assuming `(String, Throwable)` pattern. `CircuitBreakerException` uses `(String name, String state)`.
- **Welford's incremental averaging formula**: `newAvg = oldAvg + (newValue - oldAvg) / newCount` — prevents overflow from summing all values.
- **SCAN vs KEYS in Redis**: `KEYS *` blocks the Redis server on large datasets. `SCAN` uses cursor-based iteration that doesn't block.
- **`DotenvConfig.addFirst` vs `addLast`**: Spring's `PropertySource` ordering matters — `addFirst` makes .env override real environment variables, which is dangerous in production.

#### Gotchas & Pitfalls
- When removing public getters from config classes (security fix), must also update tests that assert on those getters
- Fields must be non-final if adding no-arg constructors for Jackson deserialization (final fields can't be set after construction)
- `CircuitBreaker.decorateSupplier()` wraps with `CallNotPermittedException` when circuit is open — must catch this specifically
- Word-boundary `\b` in Java regex requires double-escaped backslash in Pattern.compile: `"\\bpin\\b"`
