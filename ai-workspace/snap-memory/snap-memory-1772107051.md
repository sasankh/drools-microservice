  - `ServletInputStream` decorator that counts bytes read
  - Throws `IOException` when cumulative reads exceed configured max
  - Handles both single-byte `read()` and buffer `read(byte[], int, int)`

- **Filter Chain Pattern**: AdminAuthFilter added at Order(0), before existing RateLimitingFilter at Order(1)
- **Decorator Pattern**: SizeLimitedInputStream wraps original ServletInputStream
- **Defense in Depth**: API key auth + rate limiting + request size validation as layered security

## PROBLEM SOLVING

#### Error 1: RuleExecutor Docker Startup Failure
- **Error**: `No default constructor found` for `RuleExecutor` on Docker startup
- **When**: After adding second constructor for `maxRuleFirings` configurability
- **Root Cause**: Spring with 2+ constructors and no `@Autowired` falls back to looking for no-arg constructor
- **Solution**: Added `@Autowired` annotation to the primary `@Qualifier("ruleExecutionExecutor")` constructor
- **Prevention**: Always annotate the intended injection constructor when multiple constructors exist

#### Error 2: RuleExecutorTest Mock Failures
- **Error**: Timeout tests completed instantly instead of timing out
- **When**: After changing `fireAllRules()` to `fireAllRules(int)`
- **Root Cause**: Mocks stubbed `fireAllRules()` (no-arg) but code now calls `fireAllRules(int)`. Mockito returns default (0) for unstubbed methods
- **Solution**: Changed to `when(mockSession.fireAllRules(anyInt()))`

#### Error 3: RateLimitingConfigTest Failures (3 tests + 1 error)
- **Error**: `isAllowed` returning false for valid requests; `IllegalArgument` on ReflectionTestUtils
- **When**: After adding `maxClients` field to RateLimitingConfig
- **Root Cause 1**: `maxClients` defaulted to 0 (uninitialized int), so all new clients were rejected
- **Root Cause 2**: `ReflectionTestUtils.setField()` can't resolve fields on private static inner classes
- **Solution 1**: Added `ReflectionTestUtils.setField(config, "maxClients", 10000)` to setUp
- **Solution 2**: Used direct `Field.setAccessible()` reflection for `ClientRateData.lastAccess`

#### Error 4: Docker Port 6379 Conflict
- **Error**: Redis container couldn't bind to port 6379
- **When**: Starting Docker stack for integration testing
- **Root Cause**: Local Redis was running on the same port
- **Solution**: `brew services stop redis` before Docker testing

## DECISION LOG

#### Decision: API Key Filter vs Spring Security
- **Decision**: Lightweight `AdminAuthFilter` instead of full `spring-boot-starter-security`
- **Alternatives**:
  1. Spring Security with form login / HTTP Basic - heavyweight, requires significant test infrastructure changes
  2. Spring Security with API key provider - still adds large dependency, auto-configuration side effects
  3. Simple servlet filter with API key check - minimal, backward compatible, no new dependencies
- **Chosen**: Option 3
- **Rationale**: Design doc states "auth handled by API Gateway". This is defense-in-depth, not primary auth. A simple filter avoids adding Spring Security's complexity and auto-configuration while still protecting admin endpoints in non-Gateway deployments.
- **Trade-offs**: No role-based access, no session management, single shared key (not per-user)
- **Reversibility**: Easy to replace with Spring Security later if needed

#### Decision: Remove X-Forwarded-For Trust
- **Decision**: Always use `request.getRemoteAddr()`, ignore `X-Forwarded-For` entirely
- **Rationale**: Without a trusted proxy list, `X-Forwarded-For` is trivially spoofable. In production behind an API Gateway, the gateway should set the correct remote address.
- **Trade-offs**: If behind a proxy without proper remote-addr forwarding, all clients appear as proxy IP. Acceptable for rate limiting (shared limit is still a limit).

## KNOWLEDGE CAPTURE

#### Things Learned
- **Jackson `enableDefaultTyping`** is a critical RCE vector. Always use `activateDefaultTyping()` with a strict `BasicPolymorphicTypeValidator`
- **Access-ordered `LinkedHashMap.get()`** is a mutating operation (reorders internal linked list). Requires write lock, not read lock, in concurrent contexts
- **Spring constructor autowiring**: With 2+ constructors and no `@Autowired`, Spring looks for no-arg constructor. Always annotate the intended constructor
- **`CompletableFuture.cancel(true)`** doesn't interrupt the thread (unlike `Future.cancel(true)` from `ExecutorService.submit()`), but it marks the future as cancelled for downstream consumers
- **`ReflectionTestUtils.setField()`** fails on private static inner class fields. Use direct `Field.setAccessible()` reflection instead

#### Gotchas & Pitfalls
- Adding a new `@Value` field to a config class requires updating ALL test setUp methods that construct that class via reflection
- Changing method signatures on mocked interfaces requires updating Mockito stubs (no-arg vs parameterized)
- Local Redis on port 6379 conflicts with Docker Redis - must `brew services stop redis` before Docker testing
